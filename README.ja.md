# touchdesigner-bridge-mcp

**AIチャットからTouchDesignerを操作 — プロジェクションマッピングコンテンツを構築するための、セキュリティ最優先の*データ専用*コントロールサーフェスであり、任意コードの経路は一切ありません。**

AIチャットクライアントが[TouchDesigner](https://derivative.ca)のオペレーターネットワークを構築できるようにする、WindowsネイティブのMCP（[Model Context Protocol](https://modelcontextprotocol.io)）サーバーです。構築は、**`execute_python`スタイルの経路を持たない、型付き・スキーマ検証済みツール**の固定カタログを通じて行われます。アシスタントは、物理サーフェスへ投影するマッピング済み映像を生み出すオペレーターグラフ（TOP、CHOP、SOP、COMP、MAT、DAT、POP）を組み立てて調整します。そしてクックやレンダリングを実行し、ブリッジをいつアームするかを決めるのは、マシンの前にいる**あなた自身**です。本プロジェクトはただ1つの仕事のために作られています。**建物の外壁サーフェスへのプロジェクションマッピングコンテンツ**です — 3Dファサードレンダリングと生成テクスチャFXから、セクションごとの振り付け、プロジェクターのキーストーン／エッジブレンド、DMX／ショーコントロール、そしてメディアサーバー（Pixera / disguise）へのワイヤー接続のみの受け渡しまで。TouchDesignerとお使いのAIクライアントと並んで動作する1つのバイナリ、それとTouchDesignerに貼り付ける1行、それがインストールのすべてです。

> **ステータス:** **v0.1.0** — Rust製MCPゲートウェイとTouchDesigner内Pythonエグゼキューターで構成され、作者のHoudiniブリッジをモデルにしています。**対象:** ライセンス取得済みのTouchDesignerインストール、ビルド**2023.11k+**または**2025.30k+**。パイプラインは**AMD優先**です — NVIDIA/CUDA専用オペレーターは、対象ハードウェアでテストできないため意図的に対象範囲外としています。Windows優先です。

## Quickstart

**初めての方／コーダーではない方はここから。** ターミナルの中で生活する必要はありません。動かすまでの流れは、プログラムを1つビルド（または入手）し、そのウィンドウでボタンをいくつかクリックし、TouchDesignerを起動してTextportに小さな1行を貼り付け、AIクライアントにJSONブロックを1つ貼り付ける — それだけです。以下の番号付きの**ステップ1〜5**が各パートを詳しく解説します。

手元に用意しておくもの: ライセンス取得済みの**TouchDesigner**（2023.11k+または2025.30k+）、**Windows** PC、そしてMCPを話せるAIクライアント（Claude Desktopなど）。ディスク上の1つのフォルダが、AIが読み書きを許される**作業ディレクトリ**になります — ステップ2で選びます。

動作するセットアップまでの3ステップ（詳細は以下のステップ1〜5）:

1. **ゲートウェイを入手** （AIとTouchDesignerをつなぐ唯一のプログラム） — Releasesからビルド済みの`touchdesigner-bridge-mcp.exe`を**ダウンロード**する（コーディング不要）か、ソースから**ビルド**する（`cargo build --release --manifest-path gateway/Cargo.toml`、Rustツールチェーンが必要）かのどちらかです。これは小さなGUIとヘッドレスなMCPサーバーの両方を兼ねる単一ファイルです。
2. **設定とアーム** — ゲートウェイを実行し（GUIが開きます）、**作業ディレクトリ**を設定して**Apply**をクリックし、続いてTouchDesignerで**Textport**（`Alt+T`）にアーム用の1行を貼り付けてエグゼキューターをアームします。
3. **AIクライアントを接続** — ゲートウェイバイナリを指す小さなJSONブロックを1つ、設定に貼り付け、クライアントを完全に再起動し、ステップ5の確認を実行して、AIがあなたのTouchDesignerシーンを認識できることを確認します。

> **近道:** `python scripts/setup.py`はゲートウェイをビルドし、入力済みのClaude Desktop設定**と**、このマシンの実パスを埋め込んだTextportアームコマンドを表示します。

## なぜ他と違うのか

大半のTouchDesigner/Blender/Houdini向けMCPサーバーは、`execute_python`スタイルのツールを出荷することでアプリケーションを操作します — 設計上、任意コード実行そのものです。本プロジェクトはその逆です。

- **構造的にデータ専用。** アシスタントが呼び出せるのは、**544**個の型付き・検証済みツールからなる固定レジストリだけです。任意コードツールも、生スクリプトの経路も、自由形式のコードシンクも、意図的に**存在しません** — これらはカタログに単に存在しないため、この境界を言葉で突破することはできません。サーバーができることの集合は、列挙されたツールリストそのものです。ランタイムカナリア（`assert_no_rce_endpoints`）は、いずれかのハンドラーがコード実行エンドポイントに*見える*だけでもアームを拒否し、ビルド時のフェンス（`catalog_never_exposes_rce_tools`）は、コードを運ぶツールがカタログに到達した時点でビルドを失敗させます。
- **オペレーターごとに1つの作成・設定ツール。** すべてのTouchDesignerオペレータータイプは、それ自身の型付きツール（例: `blurTOP`、`noiseCHOP`、`gridSOP`）を持ち、ノードを作成してそのパラメータを1回の呼び出しで設定します。範囲はクランプされ、メニューパラメータはそのトークンセットに固定され、ファイルパスは何かが書き込まれる前に作業ディレクトリに制限されます。値のみ — 式やコードは決して受け付けません。
- **重い処理を実行するのはあなた。** ブリッジはレンダリング、録画、ネットワーク送信のグラフを構築して配線します。出力は設計上**ワイヤー接続のみ**です — エクスポートオペは`record`/`active`が**オフ**のまま残され、それを実行するのはあなた（またはあなたのメディアサーバー）です。アシスタントが自らレンダリング、ファイルベイク、ライブ送信を起動することはありません。
- **1つの作業ディレクトリ。** すべてのファイルの読み書きは、あなたが選んだ単一のプロジェクトフォルダに`realpath`で制限されます。その外にあるものは、シンボリックリンクやジャンクション経由でも一切到達できません。
- **検証済みのコードレーンは、抜け道ではなく例外。** コードを許す唯一の経路は、2つの狭い、**デフォルトで無効**の、同意ゲート付きレーン（GPUサンドボックス化されたGLSLレーンと、実験的なパラメータ式レーン）だけです。それぞれ、いかなる書き込みの*前にも*検証され、人間が明示的に有効化しない限りオフです。AIが自身のレーンを有効化することはできません。[セキュリティ](#security)を参照してください。

## AIとともにTouchDesignerを学ぶ

TouchDesignerは奥深く、大半の人がつまずくのは空のネットワークを前にしたあの瞬間です。このブリッジは、腰を据えて実際にTouchDesignerを*学ぶ*ための、ガイド付きで低リスクな方法です — あなたが望むものを説明すると、AIがライブセッション内でそれを構築し、あなたはオペレーターネットワークが形になっていく様子を見守ります。

- **型付きツールが学習の足場になります。** すべての機能は固定された型付き・検証済みの操作なので、AIは*本物のTouchDesignerオペレーター*にしか到達できません — ソフトウェアが実際に行えることの外へさまよったり、存在しないステップを発明したりはできません。ツールリストはTouchDesignerの構成の仕方を映しており（TOP/CHOP/SOP/COMP/MAT/DAT/POPのファミリー）、AIを縛るサーフェスが、同時にアプリケーションの構造をあなたに教えてくれます。
- **見ているのであって、盲目的に走らせているのではない。** すべての操作はゲートウェイGUIのライブ監査ログにストリーミングされるので、稼働中のTouchDesignerセッション内でAIの作業をステップごとに*見る*ことができます — ネットワークが目の前でノードごとに構築されていきます。
- **ミスは可視で、コストが低い。** 型付きで検査可能なサーフェスは、どんな誤ったノードや見誤ったパラメータも見つけ、元に戻し、修正するのを容易にします。AIが行うことはどれも、任意コードを実行したり、プロジェクトフォルダ外のファイルに触れたりしません。だから、まずいステップは災害ではなく、捕らえて学ぶものです。
- **レシピレイヤーは組み込みの家庭教師。** `recipe_reference`は、順序立てたステップ、各段階で植えるべきランドマークのタップ、そしてそれを検証する軽い読み取りを備えた、66個のツールマッピング済みワークフローレシピを運びます — 本物のファサードコンテンツがどう構築されるかの、ブラックボックスではない実践例です。
- **コードの書き方を、安全に学ぶ。** アートがGPUシェーダーや自己計算するパラメータを必要とするとき、AIはその機会を*浮かび上がらせて*教えます — 自ら生のコードに手を伸ばすことは決してありません。`glsl_reference`はGLSLシェーダーを、`expr_reference`はパラメータ式のサーフェスを、`code_reference`はどのレーンが何を運ぶかと同意のハンドシェイクを説明します。コードは、同意された検証済みレーン（`set_glsl` / `set_expr`、デフォルトで無効）またはあなた自身の手を通じてのみ入ります — レシピステップは、こうした箇所を`glsl_opportunity` / `expr_opportunity`の合図で示します。

**率直なカバレッジ — 対象範囲の内と外。** 誇張なし:

- **オペレーター:** カタログは**509個のオペレーターツール**を公開します — 対象環境におけるTouchDesignerのオペレーターセットのほぼ完全な一部です（TOP 106 / CHOP 137 / SOP 79 / COMP 30 / MAT 10 / DAT 51 / POP 96）。NVIDIA/CUDA専用オペレーターは意図的に対象範囲外です（AMD優先の対象環境ではテスト不能）。
- **コード:** 2つの検証済みレーン — GLSLシェーダー（`set_glsl`）と単一行のPythonパラメータ式（`set_expr`） — は、明示的な同意の背後で**デフォルトで無効**として出荷されます。`*_reference`ツールがそれらを教え、テキストを提案します。DAT/コールバックのPythonは貼り付け受け渡しのみ — 提案され教えられますが、ブリッジが実行することはありません。
- **ワークフロー:** 10のプロジェクションマッピング領域にわたる**66個のツールマッピング済みレシピ**。コアなファサードレーン（セクションごとのリグ、サーフェス上の映像、振り付け、マスキング、リアルタイム入力、アライメント、出力の受け渡し）はライブ実証済みです。いくつかのレシピ（マルチプロジェクターブレンド、および生成／ポイントクラウド／カメラの各レーンの一部）は構築され機構検証済みですが、まだ網羅的なライブスイープは済んでいません — 過大に述べるのではなく、ここで明示します。
- **意図的に対象範囲外:** 任意コードの経路すべて（設計上、存在しません）、そしてプロジェクションマッピングコンテンツ制作以外のTouchDesigner領域。

## できること

ゲートウェイが動作しTouchDesignerがアームされたら、AIチャットクライアントで直接、次のように話しかけられます（パスは、設定した1つの作業ディレクトリからの相対パスです）:

- 「この建物の`.obj`を、オルソカメラを通して暗いプレートの上に4Kでレンダリングして。」
- 「生成的なノイズとフィードバックのフィールドを作って、ファサードコンテンツとしてタップして。」
- 「`section_00.obj … section_07.obj`をインポートして、このクリップを各ファサードサーフェスに叩き込んで。」
- 「タイムラインにわたって各セクションを現していく、下から上への光のスイープをアニメーションして。」
- 「このドローンのポイントクラウドを読み込んで、スキャンした点にスプライトをインスタンスして。」
- 「4コーナーのキーストーンを追加して、HAPファイル出力を配線して — 録画は私が押すから。」
- 「完成したコンポジットを、ブレンドされた継ぎ目で重なり合う2台のプロジェクターに分割して。」
- 「投影と同期して、CHOPからArt-Netフィクスチャーを駆動して（ワイヤー接続のみのままで）。」
- 「セクションごとのエミッションをリアルタイムで駆動するように、OSC入力を配線して。」
- 「GO、ループ、LTCタイムコード同期を備えた、タイマー駆動のキューショーをセットアップして。」
- 「コントロールグリッドのリマップで、コンポジットを曲面に沿うようにワープして。」
- 「今シーンにはどんなオペレーターがあって、TouchDesignerはどれくらいメモリを使ってる？」

## 仕組み

```
  AI / MCP client  ──stdio──▶  touchdesigner-bridge-mcp  (one binary: GUI + headless MCP gateway)
                                        │  loopback HTTP  (127.0.0.1:9980, X-TDMCP-Token)
                                        ▼
                               a data-only executor armed inside your live TouchDesigner session
```

ブリッジは2つのプロセスから成り、両者は1つのファイル`~/.touchdesigner-bridge-mcp/arm.json`を通じてランデブーします。

- **ゲートウェイ**（`gateway/`、Rust製バイナリ） — 唯一のAI入口であり、クライアント側インストールのすべてです。これは小さなGUI（作業ディレクトリを設定し、すべての呼び出しのライブ監査ログを見る）**と**、AIクライアントがstdio経由で話しかけるヘッドレスなMCPサーバーの**両方**です。どちらになるかは、起動時に環境変数`TDMCP_GW_HEADLESS`で選ばれます。ゲートウェイは型付きスキーマ、入力検証（クランプ／enum／必須キー／パス制限）を所有し、各オペレーターツールを、ループバックHTTPでエグゼキューターへ中継する前に、汎用の`create_op` + `set_par`へと落とし込みます。これが入口側の唯一のセキュリティ絞り込み点です。
- **エグゼキューター**（`td_executor/`、Python） — `arm.py`によって稼働中のTouchDesignerセッション*内部で*アームされる、小さなデータ専用ハンドラーレジストリです。検証済みの要求を、TouchDesignerのメインスレッド上でオペレーターグラフに適用します。使用するのはPython標準ライブラリとTouchDesigner自身の組み込み`td`モジュールのみ — **サードパーティパッケージは一切同梱も再配布もされず**、`pip install`するものはありません。

ゲートウェイは509個の型付きオペレーターツールを公開しますが、そのすべてを同じ2つのエグゼキューター動詞（`create_op` + `set_par`）へ*落とし込む*ため、サーフェス全体が1つの検証済みパラメータガードに漏斗のように集約されます。[ARCHITECTURE.md](ARCHITECTURE.md)を参照してください。

## 必要条件

1. **TouchDesigner** — ライセンス取得済みのインストール、ビルド**2023.11k+**または**2025.30k+**。エグゼキューターはTouchDesigner自身の組み込みPython内で動作します。
2. **Rustツールチェーン**（stable） — ゲートウェイを自分で**ビルド**する場合のみ必要です。Releasesからビルド済みの`.exe`をダウンロードするなら不要です。[rustup.rs](https://rustup.rs)が`cargo`を提供します。
3. **Python 3.10+** — オプションの`scripts/setup.py`ヘルパー（およびエグゼキューターのテストスイート）を実行する場合のみ必要です。エグゼキューター自体はTouchDesignerの組み込みPythonで動作し、こちらではありません。
4. **MCPクライアント** — Claude Desktop、またはstdio MCPサーバーを起動できる任意のクライアント。
5. **Windows** — 主要プラットフォームです。対象パイプラインは**AMD優先**です。NVIDIA/CUDA専用オペレーターは意図的に対象範囲外です。

## ステップ1 — ゲートウェイを入手

**コーディングは避けたい？** Releasesからビルド済みの`touchdesigner-bridge-mcp.exe`をダウンロードして、そのままステップ2へ進んでください — ビルドが生成するのと同じ単一バイナリです。**代わりにソースからビルドしたい**場合（またはお使いの環境向けのビルド済みバイナリがまだない場合）は、ソースからビルドします:

```sh
cargo build --release --manifest-path gateway/Cargo.toml
# or, from gateway/:
cargo build --release
```

これは1つのファイルを生成します:

```
gateway/target/release/touchdesigner-bridge-mcp.exe      (Windows)
```

ゲートウェイはGUIとヘッドレスなMCPサーバーの両方です。どちらのモードで動作するかは、起動時に1つの環境変数`TDMCP_GW_HEADLESS`で選択されます — **未設定**ならGUIウィンドウが開き、**`1`**ならヘッドレスなstdioサーバーが動作します。（通常これを手作業で設定することはありません。ファイルをダブルクリックすればGUIが開き、ステップ3の設定ブロックがAIクライアント向けにヘッドレスフラグを設定します。）

`gateway/src/tools.rs`は`reference/catalog.json`から**生成**されるものであり、手作業で編集することはありません。

## ステップ2 — GUIで設定する

**作業ディレクトリ**は、ツールが読み書きを許される唯一のフォルダです — すべてのエグゼキューターのファイル操作はその下に制限されます。これは意図的に、ソースツリーとは**別**にします。

ゲートウェイバイナリを**引数なし**で実行してGUIを開き、次を行います:

1. **Working dir**ペインを開き、既存のフォルダを入力（または貼り付け）して**Apply**をクリックします。これにより制限ルートが以後のすべての呼び出しに対してライブで更新され、`working_dir`が`~/.touchdesigner-bridge-mcp/arm.json`へマージ書き込みされます。
2. GUIを実行したままにしておきます — その**Status**ペインには、エグゼキューター（ステップ4）が到達可能になると「Armed」のピルと稼働中のTouchDesignerビルドが表示され、そのライブ監査ログですべての呼び出しを見守れます。

あとから作業ディレクトリを変更するのは、もう一度**Apply**するだけです — 再起動も再アームも不要です。

> **ファイアウォールのステップは不要です。** TouchDesigner内のWeb Server DATは`127.0.0.1`のみにバインドします — マシン外でリッスンするものは何もないので、追加すべきインバウンドルールはありません。

## ステップ3 — MCPクライアントに登録する

クライアント（例: Claude Desktop — `%APPDATA%\Claude\claude_desktop_config.json`を編集）を、**ヘッドレス**モードのゲートウェイバイナリに向けます。[`claude_desktop_config.example.json`](docs/claude_desktop_config.example.json)のテンプレートをコピーし、2つのプレースホルダーの両方を、あなたのクローンパス（Windowsでもスラッシュ`/`を使用）に置き換えます:

```json
{
  "mcpServers": {
    "touchdesigner": {
      "command": "C:/path/to/touchdesigner-bridge-mcp/gateway/target/release/touchdesigner-bridge-mcp.exe",
      "env": {
        "TDMCP_GW_HEADLESS": "1",
        "TDMCP_REPO": "C:/path/to/touchdesigner-bridge-mcp"
      }
    }
  }
}
```

どちらの環境変数も欠かせません:

- **`TDMCP_GW_HEADLESS=1`** — 必須です。これがないと、クライアントはGUIウィンドウを生成してしまい、MCPハンドシェイクが決して完了しません。
- **`TDMCP_REPO`** — クローンパスです。これにより、ゲートウェイが同梱の参照データ（`reference/recipes.json`、`reference/catalog.json`）を決定論的に見つけられます。

設定を編集した後は、クライアントを完全に終了して再度開いてください。

## ステップ4 — TouchDesigner内でエグゼキューターをアームする

TouchDesignerを開き、**Textport**（`Alt+T`）を開いて、あなたのクローンパスに置き換えたアームコマンドを貼り付けます:

```python
import os; os.environ['TDMCP_REPO']=r'C:/path/to/touchdesigner-bridge-mcp'; exec(open(os.path.join(os.environ['TDMCP_REPO'],'arm.py')).read())
```

手作業で入力する必要はありません — GUIはこの正確な1行を**Copy arm command**ボタンとともに表示し、`python scripts/setup.py`もこれを表示します。

アームが行うこと（`arm.py`）:

- ディスク上のエグゼキューターファイルを、それらをインポートする**前に**`td_executor/INTEGRITY.json`と照合して**検証**します（フェイルクローズドな改ざん検知）。
- いずれかのハンドラーが生のコード実行エンドポイントに見える場合、アームを**拒否**します（データ専用カナリア）。
- 128ビットのCSPRNGセッショントークンを**生成**し、`token` / `port` / `working_dir`を（そして同意フラグを保持したまま）`arm.json`へ書き込みます。
- `/mcp_bridge`コンポーネントを**組み立て**ます — ループバック`127.0.0.1:9980`上の**Web Server DAT**と、ディスク上の`td_executor`パッケージを読み込む薄いコールバックDAT — そして`arm.json`に永続化されるGUI**同意トグル**（Allow Expr Lane / Allow GLSL Lane）を追加します。

**いつでも再アーム**すれば、ディスク上のエグゼキューターの編集をホットリロードできます（先にモジュールキャッシュを消去します）。ブリッジの**削除**は`op('/mcp_bridge').destroy()`で行います。プロジェクトごとにアームを永続化するには、[`td_package/README.md`](td_package/README.md)を参照してください。

## ステップ5 — セットアップを確認する

1. **エグゼキューターの健全性** — TouchDesignerをアームした状態で、ブラウザまたはcurlで開きます:

   ```
   http://127.0.0.1:9980/health
   ```

   GUIの**Status**ペインにも、エグゼキューターが到達可能になると「Armed」のピルと稼働中のTouchDesignerビルドが表示されます。
2. **ツールがクライアントに表示される** — 新しいクライアントチャットで、アシスタントに`scene_info`を実行するよう頼みます。応答が成功すれば（現在のシーン、TouchDesignerビルド）、経路全体がライブであることが確認できます: クライアント → ゲートウェイ → ループバック → エグゼキューター → TouchDesigner。

両方とも返ってくれば、配線は完了です。コードレーンの有効化やトラブルシューティングを含む完全なウォークスルーは[docs/INSTALL.md](docs/INSTALL.md)を参照してください。

## 利用可能なツール

**合計544個のツール** — 7つのTouchDesignerファミリーにわたる**509個のオペレーターツール**と、**35個のユーティリティツール**です。以下に全リストを掲載しています（[docs/TOOL_CATALOG.md](docs/TOOL_CATALOG.md)にもあります）。すべてのツールは検証済みハンドラーであり、自由形式のコード経路は存在しません。任意のオペレーターの完全な型付きパラメータスキーマは、セッション中に`operator_reference`ツールへライブで問い合わせてください（`optype=<name>`）。

- **シーンを読む:** `scene_info`、`read_network`、`find_errors`、`inspect`、`top_info`、`probe_optype`、
  `mem`。
- **構築と配線:** `connect`、`set_par`、`set_par_many`、`set_flags`、`set_pos`、`delete_op`、`bind_chop`、
  `batch`（多数のオペを1往復で実行します。直接呼び出しにない機能を付与することはなく、ネストもできません）。
- **インポート:** `import_scan`、`import_segmented_model`（パーツごとのOBJから、セクションごとの`sec*`/`mat*`
  リグ一式を1回の呼び出しで構築します）。
- **デリバー（ワイヤー接続のみ）:** `save_top`（TOPの画像を作業ディレクトリへ書き込みます）、`capture_ui`、
  `write_csv`、`pulse`、`show`。
- **調べる:** `td_capabilities`（サーフェスと境界のここから始めるインデックス）、`help`、
  `operator_reference`（任意のオペレーターの完全な型付きスキーマ）、`recipe_reference`（ワークフローレシピ）。
- **コードの書き方を学ぶ:** `glsl_reference`（GLSLシェーダー）、`expr_reference`（パラメータ式）、
  `code_reference`（どのレーンが何を運ぶか＋同意のハンドシェイク） — 検証済みレーンや手貼り用にコード
  テキストを提案する読み取り専用の教え役で、コードを実行することは決してありません。
- **コードレーン（デフォルトで無効、同意ゲート付き）:** `set_glsl` / `validate_glsl`、`set_expr` / `validate_expr`。
- **デバイス制御（デフォルトで無効、同意ゲート付き）:** `device_send` — 閉じたPJLink Class-1許可リストを
  介してプロジェクターへコマンドを送ります。人間が明示的に`allow_device_control`を有効化しない限りオフです。
- **メンテナンス:** `dev_reload`。

## リファレンス

ツールカタログは、いくつかの発見可能性サーフェスに支えられています。`td_capabilities`はここから始めるインデックスです — まずこれを呼び出して、サーフェス、境界、そして物事の調べ方に方向づけしてください。

- **ツールカタログ** — [docs/TOOL_CATALOG.md](docs/TOOL_CATALOG.md)。`reference/catalog.json`から生成されます
  （オペレーターファミリー全体でおよそ17,000の型付きパラメータにわたる、あらゆる型付き操作の権威ある一覧）。これが
  *まさに*セキュリティ境界です。カタログになければ、サーバーはそれを行えません。
- **オペレーターリファレンス** — `operator_reference` MCPツールは、「オペレーターXはどんなパラメータを取るか？」に
  ライブでプローブした真実（名前、種別、パラメータごとの範囲／トークン）から答えます。
- **`help`** — オペレーターの事実（ファミリー、入力数、パラメータ名）に加え、公式Derivativeドキュメントへの
  ディープリンクを返します。Derivativeの文章は一切同梱されておらず、出荷されるオペレーターの説明はオリジナルです。
- **`recipe_reference`** — ドライブレイヤー: 順序立てたステップと慣習を運ぶ、66個のツールマッピング済み
  ワークフローレシピです（下記参照）。
- **コードの教え役** — TDのコードサーフェス向けの読み取り専用ガイド: `glsl_reference`（GLSLシェーダー）、
  `expr_reference`（パラメータ式）、`code_reference`（どのレーン＋同意のハンドシェイク）。検証済みレーンや
  手貼り用にコードテキストを提案しますが、コードを実行することは決してありません。

## プロジェクションマッピングレシピ

`recipe_reference`は、あなたのタスクを分類し、それを構築する実証済みでツールマッピングされた1つの方法を返します — 実在するツールの順序立てた並び、実際に結果を動かすパラメータ、各ステップで植えるべきランドマークの`OUT_`ヌル、そしてそれを検証する軽い読み取りです。TouchDesignerには有効なアプローチが多数あるので、レシピは適応させるための実践例であって、決して絶対の教典ではありません。66個のレシピは次の領域にわたります:

- **3Dレンダーレーン**（`facade_3d_render`） — 建物の`.obj`/`.abc`/`.fbx`/`.usd`をGeometry COMPへ入れ、
  カメラでフレーミングし、MATでシェーディングし、暗いプレートの上のRender TOPへレンダリングします。
- **生成テクスチャFX**（`generative_texture_fx`） — 主力のファサードコンテンツレーン: ノイズ →
  ランプ → トーン → トランスフォーム → コンポジット → フィードバックトレイルという、純粋に発展する
  TOPネットワークです。
- **ポイントクラウドコンテンツ**（`point_cloud_content`） — 完成したドローン／フォトグラメトリのスキャン
  （TOP内の位置データ）を取り込み、その点にスプライトやメッシュをインスタンスします。
- **カメラ／フレーミング**（`camera_match_facade`） — 仮想カメラを実際のファサードに一致させます
  （正投影のフラットマップ、または透視のレンズマッチ）。
- **セクションごとのリグと振り付け**（`per_section_material_rig`、`height_sweep_choreography`、
  `per_section_color_choreography`、`facade_cue_choreography`） — 建築セクションごとに1つのマテリアル、
  CHOP-export経由でデータ専用に駆動されます（移動する光のスイープ、セクションごとの色、あるいはキュー付き
  ショー） — 式もコードもなしで。
- **ビデオマッピング**（`segmented_facade_video_projection`、`segmented_facade_video_content`、
  `facade_mask_atlas`） — `emitmap`を介して各UV登録済みセクションに実際の映像を駆動し、グレースケール
  マスクで窓を黒に保ちます。
- **フリーフォーム／メッシュワープ**（`mesh_freeform_warp`） — メッシュワープマッパーのデータ専用版:
  コントロールグリッドのオフセットを持つ`remapTOP`のUVフィールドが、コンテンツを曲面に沿うよう曲げます。
- **プロジェクターマッピングとアライメント**（`projector_calibrated_3d`、`projection_align_and_output`、
  `multiprojector_edge_blend`） — キャリブレーション済みのプロジェクター錐台、4コーナーのキーストーン、
  そして重なり合うプロジェクターにわたるエッジブレンドされた継ぎ目です。
- **ショーコントロールとDMX**（`realtime_input_driver`、`show_control_timecode`、`dmx_artnet_output`） —
  ファサードを駆動するライブのOSC/音声/DMX/MIDI入力、キューショーを走らせるタイマー／タイムコードトランス
  ポート、そしてライトとフィクスチャ向けのDMX / Art-Net / sACN出力です。
- **出力／受け渡し**（`output_handoff`） — 完成したコンテンツをメディアサーバー（Pixera /
  disguise）へ露出するか、HAP 4Kファイルをベイクします — **ワイヤー接続のみ**で、`record`/`active`は
  オペレーターが実行できるようオフのままです。
- **2Dマルチサーフェスマッピング**（`multi_quad_mapper`） — データ専用のkantanMapper: N個のソースを、それぞれ
  自身のコーナーワープしたクアッドに載せて黒の上に合成します — すべての窓／平面／看板面に別々の映像を
  マッピングします。
- **プロジェクターキャリブレーションの取り込み**（`camera_calibration_intake`） — ターゲットのCamera COMP＋
  レンダーリグを構築し、現場のcamSchnappr / OpenCV / 測量キャリブレーション（ポーズ＋投影マトリクス）が
  そのまま差し戻せるようにします。
- **マルチプロジェクター深度**（`multiprojector_blacklevel_mask`、`projector_stack_converge`） — 暗い
  コンテンツでブレンドの継ぎ目が消えるようにする黒レベルの底上げ、そして明るさと冗長性のための
  プロジェクタースタッキング／コンバージェンス（エッジブレンドとは別物）です。
- **スピル／ガベージマスキング**（`output_spill_garbage_mask`） — コンテンツをサーフェスのシルエットに
  クリップするスクリーン空間のホールドアウト（地面／空／隣接物に光を当てない）と、柔らかい
  プロジェクターフレームのフェザーです。
- **テストパターンとリグ＆フォーカス**（`test_pattern_generator`） — データ専用のアライメントグリッド、
  クロスヘア、カラーバー、フォーカス／1:1ピクセルのフィールド、プロジェクターごとのラベル、
  コンバージェンス＆オーバーラップのマーカーを、ネイティブ解像度で。
- **メディア再生とコンポジット**（`media_clip_player`、`layer_compositor`） — 堅牢な4Kクリップ再生＋
  ギャップレスのプレイリスト、そしてメディアサーバー風のレイヤースタック（レイヤーごとの
  不透明度/ブレンド/トランスフォーム）とトランジションです。
- **ライブフィードと直接出力**（`live_media_server_feed`、`direct_projector_output`） — ライブの Spout /
  NDI / Touch / RenderStream の受け渡し、そしてプロジェクターへ直接のパフォームウィンドウ／
  Direct-Displayによるフロントオブハウスレーンです。
- **イマーシブ／ドーム／曲面**（`dome_fisheye_master`、`curved_screen_warp_blend`） — 魚眼／正距円筒の
  ドームと360マスター（キューブマップ再投影）、そして単一の広い曲面スクリーンのための円筒ワープ＋ブレンド
  です。
- **インタラクティブコンテンツ**（`vision_interactive_mask`、`audio_reactive_content`） — 存在／モーション
  マスクを駆動するライブカメラ、そして音楽（FFT / バンドエネルギー / オンセット）から構築される生成的
  ビジュアル — データ専用です。
- **テキストとタイトリング**（`text_title_content`） — データ専用のタイポグラフィ: ショータイトル、
  ローワーサード、ロールクレジット、そして`timerCHOP → choptoDAT → textTOP`ブリッジによるコード不要の
  ライブカウントダウン／時計（式なし）です。
- **パーティクルとキネティック3D**（`particle_system_content`、`instanced_kinetic_content`） — ライブの
  GPU POPパーティクルシステム（火の粉／スパーク／雪／流れ）と、アニメーションするインスタンス配列／
  キネティックなモーショングラフィックスシーンです。
- **シームレスループ**（`seamless_loop_authoring`） — 継ぎ目のない生成ループ（周期位相、または
  頭／尾のクロスフェード）をベイクし、ワイヤー接続のみでムービーファイルへ。
- **トラッキング／移動サーフェス**（`tracked_surface_content`） — 動くプロップやパフォーマーへ投影します:
  トラッキングCHOP（BlackTrax / PosiStageNet / OptiTrack）がデジタルツインのトランスフォームをコード不要で
  駆動します。
- **LEDウォール／ピクセルマップ**（`led_wall_pixelmap_feed`） — Novastar / Brompton / Linsnの
  LEDプロセッサが取り込む正確な総解像度で、キャンバスをパネルごとのタイルへ切り分けます。
- **イマーシブルーム**（`immersive_room_mapping`） — 完全に囲む多壁＋床／天井のルーム。共有された3Dシーン
  から扇状に展開する、サーフェスごとに1つのキャリブレーション済みカメラ（床／強制遠近のアナモルフィック
  モード）です。
- **透過サーフェス**（`sheer_surface_mapping`） — スクリム／ガーゼ／HoloGauze／フォグ／ウォータースクリーンの
  コンテンツ準備。必須の黒潰し、リアプロジェクションのミラー、そして俳優に安全なホールドアウトを備えます。
- **信号取り込み**（`signal_ingest_remap`） — ライブの SDI / HDMI / NDI / ST-2110 / Syphon-Spout ソースを
  キャプチャしてサーフェスへリマップします — 出力レーンの取り込み側の双子です。
- **カラーデリバリーと均一性**（`color_grade_lut_delivery`、`projector_color_uniformity`） — LUT / OCIO の
  デリバリーカラーパイプライン、そしてマルチプロジェクターアレイにわたるホワイトポイント／ガンマの一致です。
- **マルチゾーン出力**（`multizone_independent_outputs`） — N個の独立した出力ゾーン。それぞれが自身の
  コンテンツ、解像度、宛先を持ちます（1つにまたがるエッジブレンドされたウィンドウとは別物）。
- **ショー自動化と安全**（`scheduled_playback_dayparting`、`timecode_chase_slave`、
  `emergency_blackout_and_standby`、`confidence_monitor_foldback`） — 無人の時刻別デイパーティング、
  外部のLTC/SMPTEタイムコードへのチェイス、即時のDBO／スタンバイ、そしてオペレーター確認／フォールドバックの
  タップです。
- **ライブイベントグラフィックス**（`corporate_stage_graphics`） — カンファレンス／基調講演のステージ向けの、
  IMAG＋ローワーサード＋ホールディングスライド＋カウントダウンのパッケージです。
- **オペレーター制御とショーオペ**（`operator_control_panel`、`show_health_watchdog`） — オペレーター自身の
  画面上／TouchOSCの制御サーフェス、そしてアラームオーバーレイ付きのシステムヘルスウォッチドッグ
  （fps / ドロップフレーム / GPU温度）を構築します。
- **裸眼3DコーナーLED**（`anamorphic_corner_led_3d`） — 単一のオフアクシスのヒーローカメラを2面へ分割して、
  90°のコーナーLEDウォールにわたる強制遠近の3Dを実現します。
- **ライダーと輪郭**（`lidar_presence_interaction`、`line_contour_mapping`） — 2Dレーザースキャナーからの
  インタラクティブな床／壁、そして建物の実際の建築をなぞるアニメーションのエッジ／輪郭の光の線です。
- **ショー音声**（`show_audio_playback`） — サウンドトラック再生＋マルチチャンネル／空間のスピーカー
  ルーティング＋A/Vタイムコードロック（音声OUTレーン。他のすべての音声レシピは入力専用です）。
- **放送とIoT**（`st2110_ip_video_out`、`mqtt_iot_input`） — SMPTE ST 2110のビデオオーバーIPデリバリー
  （PTP）、そして入力ドライバーファミリーを拡張するMQTT／ビル自動化トリガーです。
- **コンテンツパイプライン**（`projector_plan_tables`、`uv_template_export`、
  `structured_light_calibration_patterns`、`notch_block_playback`） — スロー／レンズの計画シート、

  Notchの`.dfx`ブロック再生のスキャフォールドです。

TouchDesignerの仕事はコンテンツ制作であり、実際のサーフェスへの物理的なワープ／ブレンドは、下流のメディアサーバーが行います。レシピレイヤーがどう配線されているかは[ARCHITECTURE.md](ARCHITECTURE.md)を参照してください。

## 落とし穴

レシピがエンコードしている、TouchDesigner特有の罠をいくつか挙げます:

- **作成ツールはタプレットのベクトルを取り、`set_par`は生の成分を取ります。** 作成ツールは`color`:[r,g,b]と
  `resolution`のタプレットを公開します。生の成分名（`colorr`）や`pars{}`ラッパーを*作成*ツールに渡すと、
  黙って落とされます。生の`colorr`/`tx`には`set_par`を使ってください。
- **新規の`geometryCOMP`には、レンダー／表示フラグを持つデフォルトのトーラス子が付いてきます。** それを
  （`delete_op`で）削除し、インポートした`fileinSOP`のレンダーフラグをオンにしてください。さもないと両者が
  レンダリングを競い合います。
- **Render TOPは、カメラ／ジオメトリ／ライトを入力への配線ではなく*パラメータ*で参照します。** その出力は
  透明です — 読み取れるビューティパスにするには、暗い`constantTOP`の上に合成してください。
- **256/1280解像度の罠は本物です。** ジェネレーター（`noiseTOP`、`rampTOP`）は小さなデフォルトを継承します。
  4Kデリバリーには`outputresolution=custom`＋`resolutionw/h`を設定してください。非商用ビルドは出力を1280に
  制限します。
- **CHOP-exportがパラメータを駆動するのは、エクスポーターのビューアがアクティブで、かつ強制クックがある
  ときだけです** — Exportフラグ単独では何も起きません。`bind_chop`はこれを処理します。手動のエクスポートには
  依然としてこれが必要です。
- **`import_segmented_model`はFile In SOPをCONSTANTモードに強制します** ので、TouchDesignerのデフォルト
  サンプルボックスではなく実際のOBJが読み込まれます。モデルは作業ディレクトリの下に置く必要があります。

## 設定

大半の設定はGUIで行われ、`~/.touchdesigner-bridge-mcp/arm.json`（両プロセスが呼び出しごとに新鮮に読み取る単一のファイル）へ書き込まれます。環境変数が必要なのはMCPクライアント設定だけです。

| 設定 | 場所 | 説明 |
|---|---|---|
| `TDMCP_GW_HEADLESS` | env（クライアント設定） | `1` = バイナリをヘッドレスなstdio MCPゲートウェイとして実行。未設定 = GUIウィンドウを開く。 |
| `TDMCP_REPO` | env（クライアント設定） | クローンパス。ゲートウェイが同梱の`reference/`データを決定論的に解決できるようにします。 |
| `working_dir` | GUI → Working dir → Apply | 制限ルート。すべてのファイルの読み書きはその下に`realpath`で制限されます。両レイヤーが呼び出しごとに新鮮に読み取り、**Apply**は再起動なしにライブで反映されます。 |
| `token` / `port` | `arm.json`（アーム時に生成） | CSPRNGセッショントークンとループバックポート（デフォルト`9980`）。トークンを入力したり目にしたりすることはありません。 |
| `allow_expr` / `allow_glsl` | GUI同意トグル → `arm.json` | 2つのコードレーンの同意フラグ（デフォルトで無効）。 |
| `allow_highres` | `arm.json` | 強制されるレンダー規模の上限をバイパスします（デフォルトで無効）。 |
| `min_action_interval_ms` | `arm.json` | 破壊的な呼び出しのスロットルです。 |

素の再アームは、同意フラグと作業ディレクトリを**保持**します — ジェイル（制限）を黙ってリセットしたり、レーンを反転させたりすることは決してありません。

## セキュリティ

セキュリティモデルは、サンドボックスではなく**境界そのもの**です。完全な脅威モデル、率直な限界、そして開示連絡先は[SECURITY.md](SECURITY.md)にあります。

- **構造的にデータ専用。** `execute_python` / `eval` / `run` / シェルのツールは存在しません。ランタイム
  カナリア（`assert_no_rce_endpoints`）、ランタイムのoptypeガード（`check_optype_allowed`。`script` /
  `execute` / `cplusplus`オペレーターと`evaluateDAT`を拒否します）、そしてビルド時のフェンス
  （`catalog_never_exposes_rce_tools`）がこれを強制します。
- **層状のパラメータガード。** 型付きサーフェスは汎用の`set_par`へ落とし込まれるため、本当の境界は、
  TouchDesignerの約17,000パラメータのサーフェスにわたるエグゼキューターの`check_par_allowed`です:
  コードポインターのパラメータ名（`callbacks` / `*script` / `datexpr`）の全域的な拒否、Sequence
  ブロックインデックスの正規表現による一般化を伴うレビュー済みのインラインコードシンクの拒否リスト、そして
  **フェイルクローズドな許可リスト**により、未知または新しいパラメータは黙って通されるのではなく拒否されます。
  これはクローズドソースのサードパーティサーフェスに対する拒否リストです: 独立したレッドチームレビューは
  実働するRCEバイパスを見つけませんでしたが、これは残余リスクであって、証明済みで完全な境界ではありません —
  [SECURITY.md](SECURITY.md)に率直に述べています。
- **ループバック＋自動生成トークン。** Web Server DATは`127.0.0.1`のみにバインドします。アームは128ビットの
  CSPRNGトークンを生成し、`X-TDMCP-Token`として提示して`secrets.compare_digest`で比較します。クロスオリジン
  （非ループバックの`Origin`/`Host`）リクエストはすべてのエンドポイントで拒否され、ループバックCSRF／
  DNSリバインドのクラスを閉じます。ボディの上限がメモリDoSを防ぎます。
- **`realpath`で制限された作業ディレクトリ。** すべてのファイル操作は1つのルートに対して解決され再チェックされ、
  シンボリックリンク／ジャンクションによる脱出は閉じられています。設定ディレクトリ（トークン＋同意）と
  エグゼキューターの信頼ルート（`td_executor/*.py`、`INTEGRITY.json`、`arm.py`）は、作業ディレクトリの内側で
  あっても立ち入り禁止であり、書き込みツールは拡張子のホワイトリストを強制します。
- **整合性のピン留め。** `INTEGRITY.json`はすべてのエグゼキューターの`.py`をハッシュでピン留めします。アームと
  `dev_reload`は**インポートの前に検証**し、いかなる不一致やピン留めされていないハンドラーに対しても
  フェイルクローズドします。率直な上限: これは改ざん検知であって、すでにインストールディレクトリへ書き込める
  攻撃者に対する境界ではありません — OSのファイルパーミッションが信頼のルートです。
- **出力はワイヤー接続のみ。** 録画／ライブ送信のグラフは`record`/`active`をオフにして構築されます。それを
  実行するのはあなたです。
- **2つの検証済みコードレーンはデフォルトで無効かつ同意ゲート付き。** `glsl_v1`（`set_glsl`/`validate_glsl`、
  GPUサンドボックス化 — 最悪でも回復可能なドライバータイムアウト）と`expr_v1`（`set_expr`/`validate_expr`、
  ASTの正の許可リスト。ここでの検証ギャップはホストコードになりうるため**EXPERIMENTAL**として出荷）。
  どちらも書き込み前に検証し、エグゼキューターが権威を持ち、監査され、書き込み経路は単一です。AIが自身の同意を
  反転させることはできません — `/mcp_bridge`コンポーネントとそのGUIトグルは、すべての変更ツールで
  `assert_writable`により拒否され、フラグは立ち入り禁止の設定ディレクトリに存在します。
- **強制される規模の上限。** アドバイザリーのガバナーはアドバイザリー優先ですが、ハードな上限が、破滅的で
  ドライバーを殺す規模（次元ごとの解像度 > 16384 px、インスタンス／パーティクル数 > 5,000,000、
  レンダーパス > 256）を拒否します。これは人間ゲート付きの`allow_highres`フラグでのみ上書き可能です — なので
  正当な4K/8Kデリバリーは通りますが、暴走した`set_par`がディスプレイドライバーをハングさせることはありません。
- **想定される姿勢: ループバック、単一の信頼できるユーザー、信頼できるマシン。** トランスポートはローカルホスト上に
  留まることを意図しています。AIは半信頼の入力として扱ってください。

単一の信頼できるマシン以外でこれを実行する前に、[SECURITY.md](SECURITY.md)を読んでください。

## トラブルシューティング

完全な表は[docs/INSTALL.md](docs/INSTALL.md)にあります。手早いチェックリスト:

- GUIの**Status**ペインが、お使いのTouchDesignerビルドとともに**Armed**と表示され、
  `http://127.0.0.1:9980/health`が応答すること。
- MCPクライアント設定が、`TDMCP_GW_HEADLESS`を`1`に設定して、ビルドされた`touchdesigner-bridge-mcp.exe`を
  指していること（これがないと、バイナリはGUIを起動し、ハンドシェイクは決して完了しません）。
- `TDMCP_REPO`がクローン（`reference/recipes.json`を含むフォルダ）を指していること。さもないと参照／レシピの
  ルックアップが失敗します。
- 設定を編集した後、クライアントが完全に再起動されたこと。
- ツールに渡すファイルパスが、設定した作業ディレクトリの**内側**にあること。
- アームが「integrity pre-check FAILED, refusing to arm」と報告する場合、マニフェストを再生成せずに
  エグゼキューターファイルが変更されています — `python scripts/gen_integrity_manifest.py`を実行してください。
- Expr/GLSLレーンの呼び出しが拒否される場合、それらのレーンはデフォルトで無効です — `/mcp_bridge`の同意トグルを
  オンにしてください（`arm.json`に永続化されます）。

## 開発とテスト

エグゼキューターのテストにはTouchDesignerライセンスは**不要**です — 偽のTDシーン
（`td_executor/tests/_tdmock.py`）に対して実行されます — なので、セキュリティ不変条件はどんなマシンでも証明できます。変更をオープンする前に、4つのチェックすべてを実行してください:

```sh
# 1. Executor unit tests — offline, no TouchDesigner required.
python td_executor/tests/run_tests.py

# 2. Gateway tests — includes the build-time boundary fences (catalog_never_exposes_rce_tools,
#    code_named_params_are_the_known_reviewed_set, reserved placement args, unique names).
cargo test --manifest-path gateway/Cargo.toml

# 3. Registry consistency — the gateway catalog and the executor endpoint set agree.
python scripts/audit_registry_consistency.py

# 4. Recipe validation — every recipe maps to real, shipped tools.
python scripts/validate_recipes.py
```

エグゼキューターを**何か**編集した後は、整合性マニフェストを再生成してください。さもないと次のアーム／リロードがフェイルクローズドします:

```sh
python scripts/gen_integrity_manifest.py            # write/refresh the manifest
python scripts/gen_integrity_manifest.py --check    # CI mode: nonzero if stale
```

完全なビルド／テスト／アームのループと、リロードのライフサイクルについては[CONTRIBUTING.md](CONTRIBUTING.md)を参照してください。
