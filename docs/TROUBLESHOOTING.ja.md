# トラブルシューティング

生きたドキュメントです — ブリッジがテストされるにつれて成長します。各項目：**症状 → 原因 → 対処**。

## 接続とアーム

**クライアントに `touchdesigner` サーバーは表示されるがツールが公開されない、あるいはハンドシェイクがハングする**
- ゲートウェイがヘッドレスのMCPサーバーではなく **GUI** を起動しました：クライアント設定の `env` に
  `TDMCP_GW_HEADLESS` が設定されていません。
- 対処：`claude_desktop_config.example.json`／実際の設定の `touchdesigner` ブロックに
  `"TDMCP_GW_HEADLESS": "1"` を追加し、クライアントを完全に終了して再度開き、バイナリを
  起動し直させてください。

**ツール呼び出しが接続エラーまたは HTTP 403 で失敗する**
- TouchDesigner がアームされていないか、`arm.json` が古くなっています（エグゼキューターが待ち受けて
  いないか、ゲートウェイが提示するトークンがエグゼキューターの発行したものと一致しなくなっています）。
- 対処：TD の Textport（`Alt+T`）でアーム行を再実行し、`http://127.0.0.1:9980/health` が応答することを
  確認してください。再アームは新しいトークンを発行し `~/.touchdesigner-bridge-mcp/arm.json` を書き換えます。
  両方のレイヤーが呼び出しごとにこれを新規に読み込むため、ゲートウェイの再起動は不要です。

**「integrity pre-check FAILED, refusing to arm」**
- `td_executor/` 配下のエグゼキューターファイルが、ピン留めされたマニフェストを再生成せずに変更されました。
  そのため `arm.py` の SHA-256 チェックが、パッケージをインポートする *前* にフェイルクローズします。
- 対処：`python scripts/gen_integrity_manifest.py` でマニフェストを再生成してから再アームしてください。
  ローカル開発時に限り、`TDMCP_INTEGRITY=0` でチェックをバイパスできます（明示的にログされます）。

**`gateway/src/*.rs` の変更（または再ビルドしたバイナリ）が反映されない**
- MCP クライアントは、セッションの間ずっと以前に起動したバイナリを保持します。Rust の再ビルドは
  ホットリロードされません。
- 対処：`cargo build --release --manifest-path gateway/Cargo.toml` を実行してから、Claude Desktop／MCP
  クライアントを完全に再起動し、新しいバイナリを起動し直させてください。（エグゼキューターの Python 編集は
  別で、こちらは再アームでホットリロードされます。RUNBOOK のロードモデルを参照してください。）

## パス / 制限（confinement）

**ファイルツールが、正しく見えるパスを拒否する**
- ファイルの読み書きはすべて、単一の **作業ディレクトリ**（`arm.json` の `working_dir`）配下に
  `realpath` で制限されます。その外にあるものは — シンボリックリンクやジャンクション経由であっても —
  拒否され、設定ディレクトリとエグゼキューターの信頼ルートは、たとえ作業ディレクトリ内にあっても同様に拒否されます。
- 対処：アセットを作業ディレクトリ配下に置き（サブフォルダは辿れます。例
  `assets/sections/section_00.obj`）、GUI の **Working dir** ペインで正しいフォルダを設定して
  **Apply** をクリックしてください（再起動も再アームも不要）。

**作成時に設定した動画／テーブルファイルのパスが空として読み取られる、または「outside working directory」として拒否される**
- 作成時パラメーターとして渡したパスは、読み取れない Windows の `\\?\` 拡張長形式に正規化されることがあり、
  相対パスは制限によって拒否されます。
- 対処：まずノードを作成し、その後で作業ディレクトリ配下の **絶対・フォワードスラッシュ** の値として
  `set_par` でファイルパスを設定してください。`tableDAT` の場合は、テーブルが実際にロードされるように
  `loadonstart` もオンにしてください。

## オペレーターの構築

**作成ツールが、渡した color／resolution／transform を「無視」した**
- 作成・設定ツールは **タプレットベクトル**（`color: [r,g,b]`、`resolution: [w,h]`、`t`／`r`／`s`）を
  取り、生のコンポーネント名は取りません。生のコンポーネント（`colorr`、`resolutionw`）や `pars{}`
  ラッパーを作成ツールに渡すと、それらは無言で破棄されます — 作成ツールのパラメーターではないからです。
- 対処：タプレットベクトルを作成ツールに渡す、**または** 後で `set_par` で生のコンポーネント
  （`colorr`、`resolutionw`、`tx`）を設定してください。2つの面（サーフェス）は設計上、異なる名前を使います。

**リクエストが大きさエラー（resolution／instances／passes）で拒否される**
- 強制される上限（`governor.py`）が、ドライバーを落とすような大きさをハード拒否します：次元ごとの
  resolution > 16384 px、インスタンス／パーティクル数 > 5,000,000、レンダーパス > 256。
- 対処：実際の成果物サイズに合わせて構築してください（4K/8K は余裕で通ります）。本当にそれより大きい
  大きさが必要な場合は、`arm.json` の人間ゲート付き `allow_highres` フラグが必要です。

## レンダリング / 出力が黒い

**レンダーが黒い、または空になる**
- レンダリングの前提条件のいずれかが欠けています：マテリアルが割り当てられていない（ジオメトリは MAT なしでは
  黒くレンダリングされます — また `phongMAT`／`pbrMAT` はライトも必要とし、`constantMAT` はどちらも不要です）、
  レンダリングすべき SOP のレンダーフラグがオフ、あるいはカメラがジオをフレーミングしていません。
  新規の `geometryCOMP` はデフォルトの子（トーラス）も出荷し、これがレンダリング対象を奪い合います。
- 対処：MAT を割り当て（`geometryCOMP.material` 経由）、意図した SOP に `set_flags render=true` を設定し、
  デフォルトのトーラスの子を削除し、カメラがモデルをフレーミングしていることを確認してください。`renderTOP` は
  カメラ／ジオメトリ／ライトを、配線ではなく **パラメーターパスで** 参照します。

**コンポジットまたはプレートが 256×256 でレンダーを潰す（256px の罠）**
- ジェネレーターとコンポジット系 TOP（`constantTOP`、`overTOP`、`noiseTOP`、`rampTOP`、…）は
  256×256 がデフォルトです。チェーンは無言でその解像度を継承します。
- 対処：ソースのジェネレーター **および** プレート／コンポジットの両方に `outputresolution=custom` ＋
  `resolutionw`／`resolutionh` を設定し、レンダーに合わせてください。（非商用ビルドは出力を 1280 に制限します。）

**Render TOP の出力がコンポジット時に透明に見える**
- `renderTOP` の背景は設計上、透明です。
- 対処：読み取り可能な、しっかりした背景のプレートにするため、暗い `constantTOP` の上に
  コンポジットしてください（レンダー = 入力 0、プレート = 入力 1）。

## アニメーションとエクスポート

**CHOP アニメーションがターゲットのパラメーターを駆動しない**
- エクスポートノードの Export フラグを設定する **だけ** ではターゲットを駆動しません。TD は
  チャンネル→パラメーターのマッピングをクック時の副作用としてのみ導出し、エクスポーターの Viewer が
  アクティブでなければなりません。手動で構築したエクスポートブロックで、ビューアーをアクティブに
  しない／強制クックしないと、ターゲットは Constant モードのまま動きません。
- 対処：**`bind_chop`** を優先してください — これは専用の renameCHOP を構築し、
  `exportmethod=autoname` ＋ `autoexportroot` を設定し、エクスポーターの Viewer Active フラグをオンにし、
  マッピングが解決するよう強制クックし、`driven` を正直に報告します（ターゲットに式を書き込むことは
  決してありません）。ブロックを手作業で構築する場合は、renameCHOP のビューアーをアクティブに保ち、
  ソース CHOP がクックしていることを確認してください（アニメーションソースは毎フレームクックします）。

**autoname エクスポートがターゲットのマテリアル／パラメーターに解決しない**
- autoname はチャンネル名（`matNN:emitr`、`secLevelNN:opacity`）を **兄弟（siblings）** に対して解決します。
  エクスポーターとターゲットは親を共有していなければならず、チャンネル名はターゲットの `op:par` と
  正確に一致していなければなりません。
- 対処：エクスポート null をターゲットと同じ親の下に置き、`renameto` のスペルを確認してください。
  ターゲットのパラメーターを `inspect` すると、駆動されているものはエクスポート null をソースとして
  `ParMode.EXPORT` と読めます。

## 出力 / 引き渡し

**出力オペレーターが、そうすべきでないときに動作している（録画または送信している）**
- 出力オペレーターは `active`／`record` を **オン** にしてデフォルト設定します（例 `dmxoutCHOP.active`）が、
  このブリッジは出力を **配線のみ（wire-only）** で構成します — ブリッジはそれらをオフにし、オペレーターが
  それらを発火させます。
- 対処：これは想定どおりです — ブリッジは `moviefileoutTOP.record`、`dmxoutCHOP.active`、NDI/Spout 送信、
  ウィンドウの開閉を **オフ** のままにします。レンダー／録画／ライブ送信の発火は、TouchDesigner 内で
  行われる人間のゲート付きステップです。

## コードレーン

**`set_glsl`／`set_expr`（または `pixeldat`／パラメーター式の引き渡し）が拒否される**
- 2つのコードレーンは **デフォルトオフ** で同意ゲート付きです：`arm.json` の `allow_glsl`／`allow_expr`。
  AI は自身のレーンを有効化できず、生の `set_par` パス上の `pixeldat` は拒否されます — `set_glsl` を
  通さなければなりません。
- 対処：人間が TouchDesigner の `/mcp_bridge` にある **Allow GLSL Lane**／**Allow Expr Lane** トグルを
  切り替えます（`arm.json` に永続化され、新規に読み込まれます — 再アーム不要）。それまでは、`*_reference`
  ツールが手作業で貼り付けるシェーダー／式のテキストを提案します。

**`callbacks`／`*script`／`datexpr` 系パラメーターの `set_par`、または `evaluateDAT` が拒否される**
- これらはコードポインター／コードシンクのパラメーターおよびコードを評価するオペレーターであり、
  すべてのオペレーターに対してパラメーターガード（`check_par_allowed`／`check_optype_allowed`）が
  拒否します — バグではなく、データ専用の境界です。
- 対処：データ専用のオーバーライドはありません。意図された非コードのパス（例：アニメーションには
  `bind_chop`、同意の裏でのシェーダーには `set_glsl`）を使用してください。

## 診断

**`find_errors` が古い、またはすでに修正済みのエラーを報告する**
- エラー状態は最後のクックを反映します。修正以降に再クックしていないノードは以前のエラーを
  抱えたままであり、エグゼキューターは TD が現在保持している内容をそのまま読みます。
- 対処：ノードをクックし（またはフレームを進める／読み取りを再実行し）、再確認してください。現在の配線を
  確認するには `scene_info`／`read_network` を、古い行を信頼する前に単一ノードのライブなパラメーター
  状態を確認するには `inspect` を使用してください。

## リファレンス

ツールの正確なパラメーター、オペレータータイプ、あるいは TouchDesigner の挙動が不明なときは、以下が
信頼できる情報源です — すべてオフラインで、ネットワークは不要です：

- **`operator_reference` MCP ツール** — 1つのオペレーター（`optype=<name>`）の正確な型付きパラメーター
  スキーマを、バンドルされたカタログからライブで回答します。セッション内からパラメーター名を確認する
  最速の方法です。
- **`recipe_reference` MCP ツール** — ツールにマッピングされたワークフローのレシピ（`classify=<task>`）を、
  順序付きのステップ、各段階に立てる目印の `OUT_` null、それを検証する軽量な読み取りとともに提供します。
  ファサードコンテンツがどう構築されるかの実例です。
- **`help` と `td_capabilities` MCP ツール** — オペレーターの事実（ファミリー、入力数、パラメーター名）に
  加え、公式の Derivative ドキュメントへのディープリンク、そしてデータ専用の境界／ガバナーのオリエンテーション。
- **`scene_info`／`read_network`／`top_info`／`inspect`** — ライブなシーン状態を読み、ネットワークを
  マッピングし、TOP の解像度を読み、変更の前後で単一ノードのパラメーターを確認します。
